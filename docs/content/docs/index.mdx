Build a local conversation, then inspect the services that carry it. DockerChat
combines rooms, direct messages, attachments, message history, and an operations
dashboard in a small multi-service project.

This is an educational prototype. Public room content is visible to the server;
private messages use browser-side encryption with server-distributed peer keys.
The protocol is not independently audited. Start with synthetic conversations and
read the [current security model](https://github.com/Nick-Maro/DockerChat/blob/main/SECURITY.md).

## Start the local lab

Install Docker with Compose v2 and Python 3.10 or newer for the configuration helper.

```bash
git clone https://github.com/Nick-Maro/DockerChat.git
cd DockerChat
python tools/setup_env.py
docker compose config --quiet
docker compose up --build -d
```

The helper generates independent credentials in a private `.env` and refuses to
overwrite an existing configuration. Published ports bind to `127.0.0.1` by
default. Open a second browser profile or an incognito window to try another chat
identity: tabs in one browser profile share keys and identity.

| Address | What to explore |
| --- | --- |
| `http://client.localhost` | Rooms, direct messages, attachments, and history |
| `http://dashboard.localhost` | Operations dashboard; generated password is in `.env` |
| `http://api.localhost/status` | Backend status |

If these hostnames do not resolve, add the following to your system's hosts file:

```text
127.0.0.1 client.localhost dashboard.localhost api.localhost
```

Use `/etc/hosts` on Linux/macOS or
`C:\Windows\System32\drivers\etc\hosts` on Windows. Ports 80 and 443 must be free.

## Follow the services

| Service | Responsibility |
| --- | --- |
| Preact + TypeScript | Browser interface, local identity, and encryption helpers |
| NGINX | HTTP routing and WebSocket upgrades |
| Bun + TypeScript | Signed commands, messages, and session handling |
| Redis | Message persistence and shared service data |
| Flask | Monitoring and administration |
| Go | Separate traffic-filter endpoint and forwarding experiments |

The default browser connection reaches NGINX directly; the Go filter is a separate
endpoint and does not protect every connection automatically. Its filtering is a
learning feature, not a production DDoS guarantee.

## Contribute or report a problem

Start with a focused improvement: browser integration tests, accessibility,
dashboard permissions, CSRF protection, shared replay protection, or clearer
peer-key verification. Use synthetic input in bug reports; never attach credentials
or chat history.
